## How it is run here

The paper is text-to-video (no start image, no camera). Our comparison is image-to-video with a camera command and a bidirectional Base target, so the paper's *router* is ported and the rest is kept as in our pipeline:

- `spec_v0 --policy ir:TAU --start 1 --warmup 1 --ir-prompt exp/irprompt_<task>.txt` (bundle `sdvg_<task>:<seed>:<tau>` → run name `sdvg_t<tau>_ir`).
- Draft = Fast (14B causal, 4 nodes, the same schedule as the paper's drafter); router = ImageReward-v1.0, every decoded frame of the chunk, min over frames, accept iff min ≥ τ; chunk 1 (first generated chunk) is always the target's (paper's force-reject); rejected chunks are regenerated by Base (16-step RePaint from the same seed), which is our target.
- Router prompt: a one-line description of the start image (Base/Fast themselves run unprompted), files `exp/irprompt_*.txt`.
- Not ported: the 1.3B drafter / 14B AR target pair (our target is Base-70) and the shared-KV-cache trick (Base is bidirectional).

## ImageReward calibration on our data (8 seeds × jar/castle, 12-frame chunks, min over frames)

See the table in the report. ImageReward saturates at its floor (≈ −2.28) on most camera-pan frames of every arm, so the paper's τ = −0.7 rejects almost every chunk here.
