# Multi-step chunk-wise Base (the "Base several steps" experiments)

Question: if the target is Base with several denoising steps per chunk instead of one step, does it stop collapsing?
File names `<task>_s<seed>_<arm>.mp4`; same start image, same camera trajectory, empty prompt for every arm.

| arm | what it is |
|---|---|
| always16_every_chunk_base16 | every chunk after chunk 0 regenerated by Base with 16-step RePaint (full CFG) on the whole prefix — the multi-step counterpart of the one-step "target only" null arm (9/24, "quality ceiling") |
| every2nd_base{1,4,8,16}step | every 2nd chunk regenerated by Base with 1 / 4 / 8 / 16 steps, the other chunks are Fast (9/22 step sweep) |
| exactspec_cfg5_onestep_target | the exact speculative sampler with the one-step CFG-5 target, same seed, for contrast |
| ref_base70_target, ref_fast_alone | Base-70 and Fast alone, same seed |

Only castle s4321 and jar s9999 have always16 (the other always16 runs were cancelled at the time because each took longer than Base-70).

`side_by_side/`: `<task>_s<seed>_base_fast_always16[_exactspec].mp4` (Base | Fast | always16 [| exact spec]); `<task>_s1234_base_step_sweep_1_4_8_16.mp4` (Base | 1 | 4 | 8 | 16 Base steps).

What to look for: with 16 steps the colour stays stable (no wash-out; jar flicker 8.6, lower than Base's 13.9), but the camera does not turn (jar stays centred while Base-70 turns to the table and wall) and chunk boundaries jump 3–8x more than inside chunks; fewer steps bring back exposure flicker, haze and colour drift.
