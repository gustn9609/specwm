# Literature survey: edge-cloud collaborative world models (2026-10-20)

Scope: web search + abstract/README reads only (no GPU work). ~45 searches (standard + extended) and ~30 page fetches on arXiv / GitHub / CVF / ACM / vendor pages. Everything below was actually found; items I could not open are marked **[unverified]**. Dates are arXiv submission dates.

Our system (for reference): LingBot-World v2 14B causal/KV-cache/4-step distilled action+camera-conditioned world model, squeezed to a 24 GB consumer GPU (GPTQ-4 weights, FP8 KV, KV window 12, 2 denoising steps) running on-device in real time; the full 14B on the cloud follows the same action stream and periodically re-anchors the device KV cache / corrects drift (speculative verify-and-correct over a 60 s horizon).

---

## A. Verdict: "first edge-cloud collaborative world model?"

**Short answer: yes, with a precise claim; no, with a loose one.**

- I found **no paper** that splits an *interactive / autoregressive / action-conditioned video world model* between a device and a cloud, and none that uses a cloud model to re-anchor or correct the KV cache / history of an on-device autoregressive video generator. Every real-time world model found (Matrix-Game 2.0/3.0, Waypoint-1.5, ABot-World-0, HY-World 1.5/WorldPlay, Hunyuan-GameCraft(-2), LingBot-World, Genie 3, Oasis/Mirage, DreamForge-World, MoWorld, StreamRender-H3) is either single-machine or "server renders, client displays".
- But **edge-cloud collaborative diffusion inference exists and is an active line** (image since 2024, *offline text-to-video* since 2025/2026), and **edge-cloud speculative decoding exists for LLMs** (many 2025–2026 papers, incl. CVPR 2026) and for **AR image generation** (CIAR, 2026). A reviewer will expect us to cite and differentiate from these.
- Safe claim: *"the first edge-cloud collaborative **interactive video world model**, and the first to use a cloud model for speculative verification and KV-cache re-anchoring of an on-device autoregressive video generator."* Unsafe claim: "the first edge-cloud collaborative video generation / diffusion system" (EcoVideo, EC-Diff, Hybrid SD, RISE, DiffusionX, MEG contradict it).

## B. MonarchRT (Infini-AI-Lab)

- Paper: *MonarchRT: Efficient Attention for Real-Time Video Generation*, Agarwal, Z. Chen, Luo, Y. Chen, Zheng, Huang, Rudra, B. Chen — **arXiv 2602.12271 (12 Feb 2026)**; code https://github.com/Infini-AI-Lab/MonarchRT (Apache-2.0); page https://infini-ai-lab.github.io/MonarchRT/.
- **What it is:** a structured *sparse attention* parameterization for video DiTs. Attention maps are factorized with Monarch (butterfly-like) matrices in an aligned block / "extended tiled Monarch" layout; the model is fine-tuned to absorb the parameterization and custom Triton kernels make it fast. Argument: video attention is not reliably sparse (periodic position-driven structure + dynamic semantic correspondences + dense mixing), so prior sparse patterns fail; Monarch captures it.
- **Claims:** up to 95% attention sparsity with no quality loss on Self-Forcing; kernel speedups 1.4–11.8x over FlashAttention-2/3/4 on RTX 5090 / H100 / B200; **16 FPS Self-Forcing (Wan2.1-1.3B based, 480p) on a single RTX 5090**; also works on bidirectional 4-step DMD Wan2.1-T2V-1.3B. Training recipe: causal init + Self-Forcing DMD (MonarchRT can be inserted at causal init).
- **Distributed / split / cloud-device / low-res + upsample?** **No.** Neither the README nor the abstract mentions any client/server, multi-machine, edge/cloud, low-resolution-then-super-resolution, or pipelining-across-devices component. Multi-GPU appears only for *training* (torchrun 8x8). Inference is a local `inference.py` on one GPU. (Beidi Chen's release tweet frames it as useful for "world models in gaming/robotics", but that is a motivation, not a system.)
- Relevance to us: an orthogonal 1.3–1.5x attention speed-up candidate for the on-device 14B (memory note monarchrt-code.md); it would need a 14B fine-tune. Not a competitor on the edge-cloud axis.

## C. Prior work on "cloud generates low-res, device super-resolves" for generative video / gaming

**Finding: I found no paper where a cloud-side *generative* video / world model emits low-resolution output and a device-side super-resolver upsamples it for interactive use.** What exists is (i) a mature *non-generative* client-side SR lineage for video delivery and cloud gaming, (ii) a few *generative-codec* works where the device regenerates from compact signals, and (iii) *single-machine* low-res-generator + streaming-SR cascades. Cite the following:

### C1. Client-side neural SR for video delivery / cloud gaming (non-generative, the "split rendering" lineage)
- **NAS** — Yeo, Jung, Kim, Shin, Han, *Neural Adaptive Content-aware Internet Video Delivery*, **OSDI 2018** (pp. 645–661): server streams low-quality video + content-specific SR DNN, client upscales; 43% QoE gain or 17% bandwidth saving. The canonical origin.
- **NEMO** (Yeo et al., **MobiCom 2020**) — real-time neural SR on mobile; **NeuroScaler** (SIGCOMM 2022) — both only confirmed via citations in CaDM (arXiv 2211.08428) and KAIST talk pages **[titles/venues from secondary sources]**.
- **River** — Jiang et al., *Real-Time Neural-Enhancement for Online Cloud Gaming*, arXiv 2501.06880 (Jan 2025): server fine-tunes SR models on repetitive game segments, keeps a lookup table, prefetches model weights to clients; ~720p@20 fps on mobile; SR runs client-side (implied by "streaming model weight to the clients").
- **Ugur, Amer, Hefeeda**, *Decoupling Video Upscaling from Rendering for Cloud Gaming*, **ACM MMSys 2025** (DOI 10.1145/3712676.3714439): decouples DLSS/FSR-style upscalers from the game renderer so cloud gaming can render low-res and upscale separately; MoQ-based system. Same group: **GameSR** (IEEE TG 2026, SR on encoded game frames, 35–56% bandwidth reduction) and **iSR** (MMSys 2026, cloud VR: one stereo view full color, other mono, reconstructed client-side).
- **Enabling Real-time Neural Recovery for Cloud Gaming on Mobile Devices**, arXiv 2307.07847 (2023): 240p→1080p on iPhone 12 at 29 ms using game-state side info.
- *A Cloud-Edge Collaborative Gaming Framework Using AI-Powered Foveated Rendering and Super Resolution* (ScienceDirect, 2023; 39.47% bandwidth reduction, SR at an edge server) **[abstract not opened; 403]**.
- CloudHide (2017) / ExtraNet (TOG 2021) / ExtraSS (SIGGRAPH Asia 2023) / PatchEX (arXiv 2407.17501): latency hiding by *frame extrapolation* on the client — relevant analogy for our "device keeps generating while cloud correction is in flight".
- Industry: NVIDIA DLSS 4/5 and GeForce NOW run upscaling **server-side**; DLSS 5 (GTC Mar 2026) is a generative neural-rendering pass demoed on a *second* RTX 5090 and is not a client-side cloud-gaming upscaler **[trade-press sources only]**.

### C2. Generative video streaming / codecs where the device regenerates
- **MEG** (arXiv 2407.07245 / 2409.05870, 2024): edge denoises, device only runs the VAE decoder on transmitted latents (image) — the closest "cloud generates latent, device decodes" diffusion split.
- **Promptus** — Wu, Liu, Tan, Hao, Zhang (PKU), *Can Prompts Streaming Replace Video Streaming with Stable Diffusion*, arXiv 2405.20032, **AAAI 2026**: server fits pixel-aligned prompts, client regenerates frames with SD (>4x bandwidth saving vs H.265 at equal LPIPS); **PromptMobile** (arXiv 2503.16112, APNET 2025) makes it run on phones (two-stage generation, inter-frame caching).
- **ReGenVC** (arXiv 2607.28144, Jul 2026): real-time generative talking-head codec; receiver's 4-step distilled DiT regenerates video from a reference frame + pose keypoints (decoder needs an 8-GPU node).
- **EcoVideo** (A1): cloud keyframes + edge interpolation/refinement — the only edge-cloud *video diffusion* split; coarse-in-time rather than coarse-in-resolution.

### C3. Low-res generator + streaming SR cascades (single machine, shows the "SR stage" is feasible in real time)
- **Ultra Flash** — Huang, Fan, Ma, …, Duan, *Scaling Real-Time Streaming Video Generation to High Resolutions*, arXiv 2606.09150, **NeurIPS 2026**: 480p streaming generator + causal streaming latent upsampler + HR decoder + 1-step SR; ~30 FPS @1K, ~18 FPS @2K on one B200; SR output fed back as context.
- **FlashVSR** (arXiv 2510.12747, CVPR 2026; 17 FPS at 768x1408 on A100), **Stream-DiffVSR** (ECCV 2026 spotlight; 0.33 s initial delay), **InfVSR** (arXiv 2510.00948), streaming-aware diffusion VSR (arXiv 2610.11746): real-time streaming diffusion SR modules a device could run.
- **TeleWorld** (arXiv 2601.00051): world model + FlashVSR-derived streaming SR module (~17 FPS at 960x1760; whole system ~8 FPS on 4 H100s). Single node.
- **Waypoint-1.5** (arXiv 2609.37107): ships a 360p and a 720p tier for different consumer GPUs — tiers, not a cloud/device split.
- **StreamRender-H3** (NVlabs Sol-Engine page): browser game engine (three.js) sends semantic maps, diffusion render on 8x GB200 with a fast causal H3 VAE; frames streamed back — a server-renders/client-displays split, no client SR.
- **Turbo-VAED** (arXiv 2508.09136): first real-time 720p video-VAE decoding on mobile — supports a "cloud sends latents, phone decodes" variant.

**Bottom line for C:** the *pattern* (cloud low-res / low-bitrate, client neural upscaling) is well established in networked systems (NAS → NEMO → River → MMSys'25/26) and in generative codecs (MEG, Promptus), but **not for action-conditioned generative world models**. If we include a "cloud low-res + device SR" split variant (Guandao 10/10 idea), position it as applying the NAS/split-rendering pattern to a generative world model, and cite Ultra Flash / FlashVSR for the SR stage.

## D. Positioning sentence and risks

**Suggested positioning sentence:**
> "Prior edge-cloud collaborative diffusion systems split *denoising steps* or *frames* of a single offline clip between a small edge model and a large cloud model (Hybrid SD, EC-Diff, RISE, DiffusionX, EcoVideo), and edge-cloud speculative decoding has been studied for discrete-token LLMs and AR image generators (PicoSpec, E2-SCI, CIAR). We instead run the *same* 14B interactive world model on both sides — memory-squeezed and few-step on a 24 GB consumer GPU, full-precision on the cloud — and use the cloud as a lagging verifier that speculatively re-anchors the device's KV-cache history over minute-long action-conditioned rollouts; to our knowledge this is the first edge-cloud collaborative interactive video world model."

**Risks (works a reviewer could cite as "already done"):**
1. **EcoVideo (ECCV 2026, arXiv 2606.30557)** — "edge-cloud collaborative video generation already exists, with bandwidth/compute-adaptive scheduling and a 2.9x speedup." We must state explicitly that it is offline, non-autoregressive, action-free, keyframe/interpolation based, and that its edge model is a 160M interpolator, not a world model; ideally run it (or EC-Diff-style step split) as a baseline on our setting, or at least argue why step/frame splits cannot give a real-time interactive stream (every frame waits for the cloud).
2. **CIAR (arXiv 2603.25463) + edge-cloud LLM speculative decoding (PicoSpec, E2-SCI CVPR 2026, Speculation-at-a-Distance)** — "device-drafts / cloud-verifies with asynchronous pipelining and adaptive acceptance is known." Differentiate on continuous latents (no logits, no exact acceptance), on display-then-correct semantics with KV re-anchoring, and on the RTT analysis (cite Speculation-at-a-Distance: per-request latency gains are bounded by RTT; our design decouples display from verification, so latency is unaffected and the cloud's job is drift control, not speed).
3. **EC-Diff (arXiv 2507.11980) "periodic cloud correction of accumulated error" + the KV-recache lineage (LongLive arXiv 2509.22622 KV recache; Hunyuan-GameCraft-2 arXiv 2511.23429 ReCache; Grounded Forcing arXiv 2604.06939; Rolling Forcing arXiv 2509.25161 attention-sink anchors; HY-World 1.5 "reconstituted context memory"/Context Forcing)** — "periodic correction / cache rebuilding for drift is known." Differentiate: those rebuild the cache from the model's *own* frames (or at prompt switches), on one machine; ours rebuilds from a *stronger reference model's* trajectory under the same actions, across a network, and we quantify the memory-degradation x repair matrix.
   - Secondary risks: **SDVG** (already our baseline), **Speculative Forcing** (same LingBot-World 2.0 base, 1.35x; reviewers will ask for a combination or a comparison), **QuantWM** (arXiv 2609.26425: 2-bit KV cache on LingBot-World-v2 / HY-World 1.5 / Matrix-Game-2, 6.2x KV compression — directly overlaps our FP8-KV/window axis; cite and compare), and **ABot-World-0** (arXiv 2607.19191: 720p 16 FPS, 19 GiB on one RTX 5090, 1.2 s TTFF) / **Waypoint-1.5** / **DreamForge-World** (14–15 FPS on a 4090) as "a world model already fits a consumer GPU without a cloud" — our answer is the fidelity gap of 14B-class models under a 24 GB squeeze, which these small models do not address.

## E. Supporting notes (for the related-work section)

**Real-time world models and their deployment (none edge-cloud):** Matrix-Game 2.0 (arXiv 2508.13009, 25 FPS on one H100), Matrix-Game 3.0 (arXiv 2604.08995, 5B, 40 FPS 720p using 8 GPUs for DiT + 1 for VAE, INT8 attention projections), HY-World 1.5 / WorldPlay (github Tencent-Hunyuan/HY-WorldPlay; 8B, 24 FPS, 28–72 GB depending on sequence parallelism; README says the report has "engineering techniques to reduce network transmission latency" — details not public), Hunyuan-GameCraft-2 (arXiv 2511.23429, 16 FPS), LingBot-World 2.0 "Infinite Worlds with Versatile Interactions" (arXiv 2607.07534, Jul 2026; distilled real-time variant 720p@60 fps claim; public script 480x832 on 8 GPUs **[secondary sources disagree on 14B vs 1.3B for the fast variant]**), Genie 3 (DeepMind, 24 fps 720p, closed), Oasis (Decart/Etched, 500M, 20 fps on H100), Waypoint-1.5 (arXiv 2609.37107, 1.28B, 512x1024 INT8 latent-FPS 72.9 on 4090 / 111.4 on 5090), ABot-World-0, DreamForge-World 0.1 (arXiv 2606.30292), MoWorld (arXiv 2607.06216, "first real-time world model on an NPU", 50 FPS), MoVerse (arXiv 2606.13376, 8 FPS on a 4090). Decart x Comcast x NVIDIA (Mar 2026 press release): Lucy real-time model on NVIDIA edge infrastructure, sub-35 ms e2e — edge *placement* of a whole model, not a device-cloud split.

**Serving-system angle:** SlackServe (arXiv 2606.15319, Jun 2026) — cluster-side serving of streaming AR-DiTs with "playout slack" as the SLO (16 H100s); StreamDiffusionV2 (arXiv 2511.07399, MLSys 2026) — multi-GPU pipeline across denoising steps and layers, 58 FPS 14B on 4 H100s. Both are single-site; useful to cite for the "continuity, not latency" SLO framing.

**KV-cache / drift correction lineage (single machine):** LongLive KV recache (arXiv 2509.22622); GameCraft-2 ReCache; Grounded Forcing asymmetric proximity recache (arXiv 2604.06939); Rolling Forcing attention-sink anchors (arXiv 2509.25161, ICLR 2026); PaFu-KV (arXiv 2601.21896), Future Forcing (arXiv 2605.30083), Head/Pyramid Forcing (arXiv 2605.14487 / 2605.13111) KV policies; "Towards Error-Free Long Video Generation" (arXiv 2606.22370); LongLive's streaming long tuning uses a Wan2.1-14B teacher to supervise self-rollouts (training-time, not inference-time). No paper found that refreshes an AR video model's KV cache from a *larger model at inference time*.

**Device-fit lineage:** QuantWM (2-bit KV, arXiv 2609.26425); Matrix-Game 3.0 INT8; ABot-World-0 low-bit DiT + light VAE (19 GiB); Waypoint INT8; Turbo-VAED mobile decoding; FlashDecoder (arXiv 2607.14898, decoder = 65% of Wan2.2 time). No paper found combining W4 + FP8/low-bit KV + KV window + 2-step for a 14B world model on 24 GB.

**Edge-cloud diffusion lineage (chronological):** Du et al. "Collaborative Distributed Diffusion-based AIGC in Wireless Networks" (arXiv 2304.03446, 2023; IEEE TCCN 2024) → MEG (2024) → Hybrid SD (Aug 2024) → EC-Diff (Jul 2025) → DiffusionX (Oct 2025) → CIAR (Mar 2026, AR image, speculative) → RISE (Jun 2026) → EcoVideo (Jun 2026, video, ECCV).

**Not found (searched, negative):** edge-cloud + "world model"; device-cloud + "KV cache" for video; cloud-low-res + device-SR for generative interactive video; two-machine speculative decoding for video diffusion; MobiCom/MobiSys 2025–26 on-device video generation with cloud assist.
