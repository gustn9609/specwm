## Verifier (exact definitions implemented; `specwm/early_exit_tf.py`)
- Token = one DiT token = 16 latent channels x (1 x 2 x 2) latent patch = a 64-dim vector (`early_exit.patch(x0)` -> `[F*(H/2)*(W/2), 64]`; 832x480 -> 3 x 30 x 52 = 4680 tokens per chunk).
- Distances are L2 norms of these 64-dim vectors divided by sigma = the median token norm of the current draft x0^(k) of the chunk (`--tf-norm draft`). Reason: the paper's oracle rel_k divides by the median token norm of the full-step output (unavailable at verification time) and the published thresholds (0.375 / 0.300) are of the size of eps = 0.24, i.e. normalized units; raw latent units (`--tf-norm none`) would make a 0.375 threshold unreachable (token norms are ~ 8-10). The calibration diagnostic (`--tf-calib`) reports both.
- Step 1: s_red(i) = min over h in H of ||x0^(1)(i) - h|| / sigma_1, H = the committed (clean) tokens of the previous chunks inside chunk c's attention window at ALL spatial positions = sink chunks {0, 1} + the 3 previous chunks (ring layout of sink 6 / window 18 / chunk 3; all previous chunks for c < 6), plus the reference frame = the VAE latent of the conditioning image (`y[4:, 0]`; the only bank entry for chunk 0). Accept if S[s_red] <= tau_red.
- Steps 2..3: s_stab(i) = ||x0^(k)(i) - x0^(k-1)(i)|| / sigma_k for active tokens (frozen tokens: exactly 0). Accept if S[s_stab] <= tau_stab. Tokens accepted at no step run all 4.
- S = 9x9 Gaussian (sd 1 token, reflect padding) per latent frame, then a Gaussian (sd 1 latent frame) over the CURRENT AND FOLLOWING latent frames of the chunk (App. A wording; `EarlyExit.smooth` is symmetric in time and is therefore overridden).
- Accepted tokens are frozen with the K/V of their acceptance step; only active tokens are forwarded (`fast_patch.ACTIVE`, index padding to a multiple of `--bucket 128`); the chunk's clean t=0 forward (`B.commit`) refreshes all K/V. Unlike the paper we do NOT merge the clean pass with the next chunk's first denoising pass (our uniform:4 arm has the same separate commit, so the relative speed-up is comparable; absolute fps is lower than theirs).
- mean_steps = mean over tokens of the accepted step (4 for never-accepted), averaged over chunks (`loop.json: mean_steps`, per-chunk histogram `per_chunk_commit_hist`).

## Differences from the paper's setting (stated, not hidden)
3 latent frames per chunk instead of 4; 153 frames per clip instead of 253; single RTX PRO 6000 instead of H100; separate clean commit (no merged pass); our c2w programs instead of their random camera segments; our 832x480 prep (bicubic resize of the scene image); SDPA flash for sparse forwards.

## Threshold re-calibration (2026-10-17, GPU 5, `calib_1017/`) — arm B
Why: the paper calibrated 0.375 / 0.300 on their 4-latent-frame chunks and 253-frame rollouts; on our setting (3-frame chunks, draft-sigma
normalisation, see Verifier) they over-accept (smoke above). Rule used (task 10/17): per scene, the score quantile that matches the ORACLE
acceptance rate P(rel_k <= 0.24) with rel_k measured against the 1.3B's OWN 4-step output; the frozen value is the median over scenes.
Measurement (`calib_1017/cal.sh` -> `calib_analyze.py` -> `calib_summary.json`, mirrored into `baselines/calib.json['sf1p3b']`): 3 neutral scenes
(balloon_block_cut, easy_lake, pouring_water_into_cup) x programs P1 (forward) and P2 (turn), one process, `--tf-calib --tau-red -1 --tau-stab -1`
so that NO token is accepted during the calibration run: the context of every chunk is then the uniform:4 output (same code path) and the scores
are measured along the model's own full-step rollout (the paper's protocol), not along a collapsing early-exit rollout as in the smoke. 13 chunks x
4680 tokens per clip (pouring: 4836), 355 134 tokens in all; lock held 00:08-00:13 (5 min), peak 27.2 / 29.8 GiB.

## Learned head for the 1.3B (their Ours_H) — what it would need (not launched)
- `specwm/gap_dump.py` hard-codes the 14B (`FAST` ckpt, `fp8_swap`, random projection 5120 -> 1536, `chan_norm` from the first chunk); it has **no `--model` flag**. `gap_dump_cross.py` loads the 1.3B but stores draft-vs-14B gaps (cross-model), not the 1.3B's own 4-step gap. Needed: a `--model 1p3b` branch (V2Binding with `cfg_name="i2v-1.3B", assets_dir=FAST`, no FP8, projection 1536 -> 1536 or identity, `specwm_out/chan_norm_1p3b.pt` already exists), ~15 lines.
- `scripts/head_train.py` is model-agnostic (`cin` from the data, Huber loss, Adam 1e-3, bs 4); 30 epochs on 611 chunks took 24 s on the 14B features (same 1536-dim input).
- `spec_early_tf.py --mode early --model 1p3b` would need the 1.3B norm/proj instead of the hard-coded `chan_norm_14b.pt` / `gap_dump_v3/proj.pt` (3 lines).
- Cost: dump = 90 camera tasks x (prepare ~6 s + 13 chunks x 4 dense steps ~8 s + save) ~ 20-25 s/task -> ~40 min on one PRO 6000 (plus a warm-up); data 140 MB/task (hidden [3, 3, 15, 26, 1536] fp16 per chunk) -> ~13 GB for 90 tasks (disk: 53 GB free; the paper's 1K rollouts x 253 frames would be ~250 GB = not possible on /home). Training < 5 min. Re-running this baseline with the head on the frozen sets: same cost as the tf arm. Total ~1 GPU-hour for a 90-scene head; the smoke's calibration numbers say how far the training-free scores are from the oracle (AUROC) and hence how much a head would add.
