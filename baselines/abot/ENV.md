```

flock /tmp/gpu4.lock env CUDA_VISIBLE_DEVICES=4 /home/hk28965/specwm/baselines/abot/run.sh IMAGE PROGRAM_ID SEED OUTDIR [--offload-t5 on|off|auto] [--quant fp8-per-token|fp8-per-tensor|none]
# e.g. ... run.sh /home/hk28965/specwm/baselines/scenes/abot/desert_valley_3rd.png P2 1234 /home/hk28965/specwm/baselines/runs/abot/abot__desert_valley_3rd__P2
# batch (ONE model load for all clips — use this for the frozen generation; 10/17):
python3 /home/hk28965/specwm/baselines/abot/make_jobs.py /home/hk28965/specwm/baselines/runs/abot_jobs.json --out-root /home/hk28965/specwm/baselines/runs/abot --set abot --programs P1,P2,P3,P4,P5 --seed 1234 [--skip-done]
flock /tmp/gpu4.lock env CUDA_VISIBLE_DEVICES=4 /home/hk28965/specwm/baselines/abot/run.sh --batch /home/hk28965/specwm/baselines/runs/abot_jobs.json            # T5-resident arm
flock /tmp/gpu4.lock env CUDA_VISIBLE_DEVICES=4 /home/hk28965/specwm/baselines/abot/run.sh --batch /home/hk28965/specwm/baselines/runs/abot_t5offload_jobs.json --offload-t5 on   # (jobs made with --out-root .../runs/abot_t5offload)
```
`run.sh` reads the caption from `IMAGE`'s sibling `.txt` (empty → none), derives the per-block keys from `PROGRAM_ID`, and calls `baselines/abot/bench_abot.py` (a copy of `tools/abot/bench_ours.py`, which is left untouched) inside the ABot venv → `OUTDIR/video.mp4`, `OUTDIR/timing.json`, `OUTDIR/log.txt`.
**Batch mode** (`run.sh --batch JOBS.json [extra args]` → `bench_abot.py --batch`): `JOBS.json` is a list of `{"image", "program" (or "actions"), "seed", "out", "prompt"}`; `make_jobs.py` writes it from a scene set x programs with `out = OUT_ROOT/<set>__<scene>__<program>` and `prompt` = the sibling `.txt` (`--no-caption` for empty prompts, `--skip-done` leaves out jobs whose `timing.json` already has `frame_check_ok`). The 5B DiT + T5 + VAEs are loaded once; one warm-up stream precedes the first job, every job then runs the full per-stream reset (prompt re-encode, KV cache reset, streaming-VAE reset, fresh seed `torch.manual_seed(job seed)`), so each job's clip is identical to what the single-clip path produces (same seed → same noise) and its `timing.json` has the same fields plus `batch {file, index, size}` and `warmed_by`; `peak_*` are reset per job. Each job gets `video.mp4`, `timing.json`, `log.txt` (its own slice of the stdout); the whole stdout goes to `JOBS.log` next to the jobs file. A job that fails (exception or frame-layout check) is reported as `[ABOT_BENCH_FAILED]`, the others still run, and the process exits 1 at the end. Verified 10/17 on GPU 4: 4 jobs (desert_valley_3rd / ruins_explorer_3rd x P1, P5) in 5 min 47 s under the lock including the 67 s load, every job block 0 = 9 frames, 129/120, TTFF 0.92-0.96 s, 12.2-12.8 fps e2e, peak 32.1 GiB (T5 resident) — vs ~4 min per clip in single mode.
Keys per program (11 blocks; block b covers decoded frames [9+12(b-1), 9+12b), block 0 = [0,9); a key is set from the summed motion of the frames in the block):
P1 `W x11`; P2 and P2p `L x11`; P3 `WL x11`; P4 and P4p `WL WL WL WJ WJ WJ WJ WJ WL WL WL`; P5 `W W W - - S S S W W W` (effective switch times = block boundaries at decoded frames 33 / 57 / 93, counted from the start image at t = 0 as in `calib.json['abot'].effective_switches`: P4/P4p **2.75 s / 7.75 s**, P5 **2.75 s / 4.75 s / 7.75 s**; counted from the first generated frame instead these are 2.67 / 4.67 / 7.67 s — the 10/16 text used that convention; the P5 reaction test (`scripts/reaction_p5.py`, model abot) must use the switch list [(2.75, 0), (4.75, -1), (7.75, 1)] = still / back / forward at frames 33 / 57 / 93. The block straddling a 2.5 s boundary takes the net motion, as in `tools/abot/poses_to_keys.py`).
Note: `baselines/calib.json` "abot" and `programs/P*.npz` "abot" (written by `baselines/convert.py`) were updated on 10/17 to the same 9+12k layout (11 blocks, 129/120 frames, `block_frames` [[0,9],[9,21],...,[117,129]]) and give the same key strings as `encode_abot.py` (checked for P2 `L x11` and P5 `W W W - - S S S W W W`, switch frames 33/57/93 = 2.75/4.75/7.75 s counted from the start image at t = 0); `run.sh` reads neither file, it encodes from `encode_abot.py` directly. Scenes: `baselines/scenes/abot/` (15 of ABot's own images, `SOURCES.md`); ABot's loader centre-crops every start image to 1280x704 (`ImageOps.fit`), the identical crop is in `scenes/abot/fit1280x704/` for the other models.

ABot has no magnitude input, so there is nothing to re-scale: the P2 mismatch for ABot is +4 % (a 10 s hold = 184 deg instead of 180).
